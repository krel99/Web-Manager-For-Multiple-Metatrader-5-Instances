This system has a server component, a web interface and a metatrader 5 bot.

## Web Interface

Stack: Vanilla html, use existing CSS variables for styling in public/index.html

This should allow me to input trades. These parameters are required to be in input UI:
Required: symbol (EURUSD, GBPUSD, USDJPY, EURGBP, AUDUSD, AUDNZD, EURJPY, USDCAD, XAUUSD), direction (long|short), stop loss price, level_type (watch|order|option), valid until (time; default=20:00)
Conditionally required: limit price (required unless "market order" is checked)
Optional: take profit price, partial take profit price, level_size (default=none, options=watched|medium|large), market order checkbox (when checked: no limit price, position is opened at market on EA pickup), close time (time; default=none - this is not a date but a time on the same day as valid until), close after minutes (positive integer; alternative to close time, counts from the moment the position is filled), close manually checkbox (when checked: the EA never closes the position, I close it manually; clears and disables close time and close after minutes)

close time, close after minutes and close manually are mutually exclusive. Leaving close time and close after minutes empty also means the EA never closes the position.

None means no value, not "none"

Date field and ID will be added automatically.

Styling variables area already created at public/index.html

There is no history view. Past levels are not remembered and open positions are not tracked.

level_type is record-keeping metadata only. It does not influence whether a trade is executed; every submitted trade is executed by the EA.

## Server

Stack: Express JS

Listens on port 3001.

get requests to /<SYMBOL> will return all active trades. A trade is active while its active_until_utc is still in the future. The list intentionally is NOT filtered to "today only" so that:
  - trades using "valid_until next day" remain visible after midnight
  - filled limit orders remain visible so the EA can manage them after a restart
  - close_after_minutes trades remain visible long enough for the EA to auto-close them
post requests to /<SYMBOL> will create a new trade. Trades that are no longer active are dropped from trades.json at the same time; there is no history and no reports endpoint.

The server is also responsible for providing correct time. Inputs from the web interface are in Central European Time (which can be winter or summer). The server should work in UTC.

active_until_utc rules:
  - if close_time is set: active_until_utc = close_time_utc
  - else if close_after_minutes is set: active_until_utc = valid_until_utc + close_after_minutes + 60min buffer
  - else (manual close): active_until_utc = 23:59 local of the valid_until date, in UTC

## Metatrader 5 Bot

Polls the server every PollMinutes minutes (http://37.46.211.146:3001/<SYMBOL>); uses the chart symbol stripped to the base name (e.g. EURUSD_ecn -> EURUSD), looks for a valid base symbol from the supported list.

Inputs:
  - ServerURL
  - RiskAmount: USD risked per trade. Position size is derived from RiskAmount and (entry - stop_loss) distance using the symbol's tick size and tick value. There is no separate "capital" input.
  - PollMinutes
  - SlippagePts: deviation in points used for market entries, partial closes, and auto-close (irrelevant for limit-order entries).

Execution rules:
  - Every trade returned by the server is executed regardless of level_type.
  - order_kind=="market": opens the position at market immediately on poll. Sizing uses current ask (long) / bid (short) as the entry estimate.
  - order_kind=="limit" (default): places a Buy/Sell limit at limit_price (GTC).
  - Each MT5 order/position is tagged in its comment as "ZT:<id>" so the EA can match server trades to MT5 tickets.
  - Symbol -> magic-number mapping is fixed; only this EA's magic on the chart symbol is touched.

Position management:
  - Partial take profit: when partial_take_profit is reached, close 50% of the position rounded down to the volume step. Done at most once per id.
  - Auto-close (close_time): when close_time_utc passes, cancel any still-pending order for that id and PositionClose any open position for that id. The closing deal's real price is then reported.
  - Auto-close (close_after_minutes): once a position exists for the id, close it when (now - POSITION_TIME) >= close_after_minutes * 60. Pending orders are not affected by close_after_minutes; they expire at valid_until via the standard expiry path.
  - Manual close (no close_time and no close_after_minutes): the EA never closes the position.
  - Expiry: pending limit orders past valid_until_utc are cancelled.

The EA does not track or report closed positions.
